# 脚本 README 自动生成器

> 每次为用户生成脚本时，**必须**在脚本所在文件夹下同步生成一个 `README.md` 说明文件。

---

## 1. 触发条件

**必须使用本 skill**：
- 用户要求"生成脚本"、"创建脚本"、"写一个脚本"、"新建脚本"、"编写脚本"
- 用户要求创建任何 `.js`、`.ts`、`.py`、`.sh` 等可执行脚本文件
- 用户在对话中描述了一个自动化任务，需要生成脚本来完成

**不需要使用本 skill**：
- 用户只是修改已有脚本的某几行代码
- 用户只是询问脚本相关问题，不涉及创建新文件

---

## 2. 执行流程

### 2.1 生成脚本

按用户需求编写脚本代码，遵循项目现有代码风格：
- 使用 `const path = require('path')` / `const fs = require('fs/promises')` 等 Node.js 内置模块
- 使用 `createRequire` 从项目根 `package.json` 加载依赖
- 数据文件路径使用 `path.join(__dirname, ...)` 相对引用
- 脚本入口为 `async function main()` + `main().catch(...)` 模式
- 输出格式使用 `[index/total] ✓/✗/- name — detail` 风格

### 2.2 生成 README.md

脚本生成完成后，**必须**在同一文件夹下创建 `README.md`，包含以下章节：

#### 必选章节

| 章节 | 内容 |
|------|------|
| **标题** | `# 脚本文件名`（不含路径，仅文件名） |
| **功能** | 1-3 句话描述脚本做什么 |
| **依赖** | 列出脚本依赖的 npm 包（如 `@larksuiteoapi/node-sdk`） |
| **数据文件** | 如有输入数据文件，说明其路径和格式要求 |
| **使用方式** | ````bash\nnode path/to/script.js\n```` |
| **输出示例** | 模拟脚本运行后的控制台输出 |

#### 可选章节（按需添加）

| 章节 | 适用场景 |
|------|---------|
| **执行流程** | 脚本逻辑较复杂，需要 ASCII 流程图说明 |
| **涉及的 API** | 脚本调用了外部 API，需要列出 API 表格 |
| **注意事项** | 有重要的前置条件、权限要求、幂等性说明等 |

---

## 3. README.md 模板

```markdown
# script_name

功能描述，一句话概括脚本用途。

## 功能

- 功能点 1
- 功能点 2

## 依赖

- `package-name` — 用途说明

## 数据文件

脚本依赖 `path/to/data.json`，该文件应包含：

```json
[
  {
    "field": "value"
  }
]
```

## 使用方式

```bash
node path/to/script_name.js
```

## 输出示例

```
开始执行...

[1/10] ✓ 操作成功
[2/10] ✗ 操作失败 — 错误原因

完成！成功: 9, 失败: 1
```
```

---

## 4. 注意事项

1. **README.md 文件名**：统一使用 `README.md`（大写），不要使用 `readme.md` 或其他变体
2. **语言**：README 内容使用中文，与项目现有 README 保持一致
3. **代码块语言标注**：JSON 代码块标注 `json`，bash 命令标注 `bash`
4. **路径描述**：数据文件路径使用相对于脚本所在目录的相对路径（如 `../getGroup/data/feishu_groups.json`）
5. **输出示例要真实**：模拟的输出应反映脚本的实际逻辑，包含进度计数、成功/失败标记等
6. **不要遗漏依赖**：检查脚本中 `require` 的所有外部包，全部列入依赖章节
